# 产品定位与下一步

评估日期：2026-10-14。以本发行目录的源码和离线测试为准，不以开发者机器的登录状态或工具配置代表用户可获得的能力。

## 判断

最合适的定位是 **本地优先、Agent 辅助的个人衣橱与证据驱动整套选购助手**。核心交付是 Skill + 本地数据 CLI，可选只读 MCP/浏览器扩展提供用户授权页面的数据。当前是开发者可试用的 alpha，不是安装即用的独立应用，也不是通用购物抓取产品。

价值不在于返回更多商品，而在于回答：“已有衣服怎么穿；确有缺口时，哪件、什么颜色和尺码、凭什么适合，而且怎样组成完整一套？” 本地记录支持跨轮次记忆和用户纠正；来源与核验级别减少搜索摘要被误当成可购 SKU 的风险。

## 当前与边界

| 环节 | 当前交付 | 尚不应宣传为已完成 |
| --- | --- | --- |
| 画像和衣橱 | Skill 流程；SQLite 七类记录；可跳过照片 | 自动准确量体、科学色彩季型判定 |
| 场合与天气搭配 | 约束优先、衣物可用状态、反馈引用；天气失败降级 | 内置可用天气服务、每日自动提醒 |
| 灵感 | 外部小红书只读连接器契约 | 已捆绑小红书服务、自动读图、视觉搜同款 |
| 整套选购 | 候选和已拥有衣物分离；搜索/详情/SKU 证据分层 | 自动选中所有规格、保证合身/实时库存、自动结算 |
| 订单入衣橱 | 结构化行暂存、哈希去重、明确审核、事务入库 | 自动 OCR、跨平台订单批量读取、Mac 适配实测 |
| 可用性 | 命令行和宿主 Skill | 独立网页/桌面 GUI、云同步、多用户编辑 |
| 安全 | 最小收集、导出/删除、非可信页面约定 | SQLite 加密、安全擦除、仅靠提示词的强制隔离 |

核心 Python 仅使用标准库，不调用模型或网络。宿主决定模型与工具可用性；“本地保存”不代表模型推理从不出网。可选 commerce 连接器的离线测试不是淘宝/京东登录、页面结构、风控和真实 SKU 的线上验收。

## MVP 闭环

1. 取得持久化同意，建立少量用户确认偏好与合身衣物参考。
2. 录入已有衣物和当前可穿状态，先生成不用买的基础方案。
3. 收集场合、出行时段、用户地点；天气有来源时使用，无来源则明确未知。
4. 用户需要探索时再读取少量授权的小红书案例；文本与实际看过的图片分开。
5. 给出完整穿搭组成；明确已有、候选、泛化建议，分层说明由内到外的穿着顺序。
6. 有缺口才查商品：每个可购候选核对同一颜色＋尺码 SKU、价格条件、尺码依据和来源时间。用户要求跨平台比价时仅比较同款同 SKU；没有匹配就说明未找到，不能以相似款代替。
7. 用户反馈舒适、合身和愿意再穿程度，修正相关偏好。购买意向不是已拥有；订单也须审核。

这是目标闭环，不代表已经完成端到端模型或平台验证。渐进尝新默认一次改变一个元素，但用户的真实偏好由用户决定，发行文档不包含开发者个人肤色、尺码、城市或预算。

## 优先级

### P0：先把证据和失败状态做可信

- 补齐同款/同 SKU 身份、颜色尺码、尺码表和衣服实测的证据链；区分页面可见、实际选择、库存未知，禁止摘要价格串 SKU。
- 统一完整穿搭清单与组件链接；无法核验时给搜索词或用户链接路径，不生成假商品 URL。
- 展示登录过期、验证码、风控、缺字段、超时的下一步；有限批次、间隔请求，平台阻止即停，不自动重试绕过。
- 增加无网络、无天气、无图像、提示注入、整套预算和规格不全的行为验收，并经单独预算批准后才运行模型/平台测试。
- 保持导出白名单、来源、许可证与无真实个人数据的发行门槛。

### P1：降低日常录入和核对摩擦

- 先做只读本地查看器，查看衣橱状态、搭配、候选与证据；记录变更仍走校验 CLI，避免两套存储逻辑。
- 改进少量逐项确认、缺失字段补全、同物去重和错误恢复。经过真实用户授权验收后才考虑扩展写入界面。
- 提供经验证的连接器能力矩阵、平台安装说明和可撤销授权；不要用“配置了”代替“连接成功”。

### 后续候选，而非承诺

周计划、可选提醒、用户主动选择的视觉整理、合身反馈积累。先证明闭环留存与推荐可信度，再扩展平台。明确不追求批量采集、自动订单遍历、交易自动化或社交写操作。

## 验收与风险

离线自动测试验证存储、引用、回滚、候选分离和订单审核；场景 JSON 只是待执行清单。产品验收还应检查完整穿搭覆盖、用户指出错误后的修正、缺字段不冒充可购、授权边界和故障恢复，不能只报测试数。

主要风险是平台页面/风控变化、尺码信息不足、模型把推测当事实、过度询问带来的摩擦，以及宿主/连接器将私人资料发送出本机。项目已采用 MIT 许可证；第三方署名须保留，依赖未锁定仍是对外发布前须说明的限制。
