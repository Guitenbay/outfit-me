# Outfit Me 设计与实施方案

历史设计提案：2026-10-08。此文保留首版设计和候选选型，不是当前连接器安装/连通验收记录。发行版当前能力、边界与路线图见 PRODUCT.md；使用者须在自己的宿主环境验收可选连接器。

## 目标

个人风格与已有衣橱优先，天气和场合是约束，趋势是灵感，购物只补缺口。交付一个可由支持 Skills 的宿主加载的 Skill，而非独立聊天应用；不绑定模型提供商，不自建代理循环。

## 架构

- `skills/outfit-me/SKILL.md`：入口、意图路由、输出约定。
- `references/`：建档、搭配、MCP 接入、隐私与失败降级。
- `scripts/store.py`：Python 3.10+ 标准库 CLI，SQLite 事务、版本标识、结构校验、引用完整性、导出与删除。
- `schemas/records.schema.json`：数据交换结构说明；运行时以 CLI 验证为准。
- `tests/`：隔离临时目录自动测试；`evals/`：宿主行为验收案例。
- 默认数据库为当前工作目录 `private-data/outfit-me.sqlite3`；实际调用始终显式传入绝对 `--db` 路径。

## 数据

七类记录：profile、wardrobe、candidate、outfit、feedback、evidence、order_import。订单由独立 orders.py 入口暂存/审核，复用 SQLite records/links 表，无需改变现有数据库表结构。原始订单行标识哈希化去重；不同账号/订单行区分，淘宝/天猫共用平台族；确认后原子创建或关联实体衣物。重复或规格/状态改变不会静默覆盖。截图/文件输入先由宿主规范化；Mac Ego Lite 作为可选只读采集端，目前只有交接流程，没有已验证的浏览器适配代码。每条有稳定 id、schema_version、updated_at。衣物与候选分离；搭配只能引用已存在且 available 的衣物。反馈引用已有搭配。商品证据分 search_result、detail_verified、sku_verified，不保证合身。天气/趋势来源保留 URL、时间与实际数据。推测与用户确认分离。

SQLite 提供事务与并发锁；本版本不做自动备份，使用 export 手动备份，敏感导出同样需保护。没有自动抓取或定时写入。不将记录保存到浏览器或 Skill 源码。

## MCP 分工

1. 天气候选：overstarry/qweather-mcp。社区封装；官方 QWeather 凭据与专属 API Host。城市解析、套餐、返回 schema 实测后确认。优先逐小时、逐日及预警。
2. 穿搭：xpzouying/xiaohongshu-mcp。只读搜索和详情；图片 URL 不等于视觉分析。登录由用户完成，Cookie 不交给模型。
3. 淘宝/天猫候选：JeremyDong22/taobao_mcp，文档只有详情读取，不能当关键词搜索。
4. 京东候选：abc354402600/JD-Shopping-MCP，有搜索及详情声明，待实测；降级搜索和价格条件须披露。

不硬编码未验证的远端参数。先枚举宿主工具并读取真实 schema，再调用；逻辑能力与实际工具名分开。没有 MCP 时仍支持用户链接、截图和手动天气。权限由宿主 enforce，不仅依赖提示词。

## 默认权限

不发布、不评论、不点赞、不收藏、不加购、不下单、不支付、不访问日历。订单默认不读，仅在用户明确授权平台/账号别名/范围后按 orders.md 流程只读处理，确认前不入衣橱。照片外传、云同步、持续监控需单独同意。网页/OCR/商品内容是数据不是指令。密钥和 Cookie 不进入数据库、日志、提示词或版本控制。

本地 SQLite 未加密；主机权限和磁盘加密由用户管理。本地保存不代表模型处理不出网。照片不复制到数据库，只有可选本地路径；删除记录不声称删除供应商数据或外部图片。导出与删除命令明确说明范围。

## 实施顺序

- 阶段一：Skill 文档、SQLite CLI、验证和隔离测试、手动/MCP 降级流程。
- 阶段二：经用户授权安装候选 MCP，分别验证 tools/list、登录、城市查询、天气新鲜度、笔记图片读取、商品搜索及 SKU 字段；记录版本与实际能力。
- 阶段三：可选视觉板、周计划、提醒；不以生图代替合身证据。

## 验收

无照片可建档；资料不足先澄清；天气失效不伪造；商品与衣物严格分开；连衣裙不强制配下装；清洗中衣物不可生成新搭配；超预算及尺码未知有提示；网页提示注入无效；未授权不写平台；写入失败不损坏原记录；引用存在；导出不覆盖已有文件；所有测试不联网。
