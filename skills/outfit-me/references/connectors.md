# 外部数据连接器

本文件是调用契约，不是已经安装的 MCP 配置。当前候选仅文档核验，实际工具名、参数和返回值以宿主枚举结果为准。不要从 README 猜参数直接调用。

## 能力发现

每次新环境先查看可用 MCP 工具及 schema，形成会话内能力清单：天气实时/逐小时/逐日/城市解析；小红书搜索/详情/图片读取；各平台商品搜索/详情/SKU。记录不可用与缺权限。只读动作也可能消耗配额，遵循用户预算与服务条款。

宿主必须限制工具 allowlist；若无法隔离写工具，明确告知并建议只读封装/权限规则。不能把本文件当成安全沙箱。

## QWeather

候选 https://github.com/overstarry/qweather-mcp （社区）。文档工具：get-weather-now、get-hourly-forecast、get-weather-forecast、get-weather-warning。城市解析未确认；使用实际支持的位置参数。官方配置：https://dev.qweather.com/docs/configuration/ 。使用账户自己的 API Host 和凭据，勿照抄旧公共域名；不向用户索要将密钥粘贴进聊天。

只发送地点和所需时间，不发送体型/照片/衣橱。获取预报覆盖出门与回家时段。至少提取实际返回的温度、体感、降水、风和预警；缺失值为 unknown，不能把温度当体感。保留观测/预报时间、抓取时间、时区、来源与位置。预报目标时间不在返回范围内时不能外推成天气事实。

默认新鲜度策略（本项目建议，不是供应商 SLA）：当天搭配获取 60 分钟内缓存；逐日预报最长缓存 6 小时；用户即将出行或天气剧烈变化时重新查询。失败时可使用仍适用的缓存并标注；否则请用户提供天气或给条件式建议，不捏造数据。穿衣指数只是补充，不代替用户怕冷怕热等偏好。

## 小红书

候选 https://github.com/xpzouying/xiaohongshu-mcp 。只读：search_feeds、get_feed_detail、check_login_status（实际按枚举核实）。首次二维码登录单独经用户同意；Cookie 保留在连接器侧，不导入画像或打印。禁止 publish、comment、like、favorite 等写操作。

按需搜索 2–3 个具体词组，默认选少量相关案例，避免无上限翻页。查询可包含季节、通勤/旅行等场合、偏好风格、温度范围；不提交完整私人资料。详情所需 feed ID、安全令牌从真实搜索结果取，不猜测；令牌不写入可分享报告。

提取发布时间、来源 URL、正文依据、是否实际查看图片、配色、轮廓、层次和适用天气。未查看图片不得声称图中服装细节。可见商业合作信息要注明；看不到合作标记也不等于非广告。点赞数不能证明流行程度或商品质量；避免将旧文、重复转载、单一博主建议作为趋势定论。保存观点摘要和链接，不批量保存博主人像。

## 购物

候选：
- https://github.com/JeremyDong22/taobao_mcp ：taobao_fetch_product_info 详情，未确认关键词搜索。需要用户浏览器登录，许可证待核。
- https://github.com/abc354402600/JD-Shopping-MCP ：jd_search_products、jd_get_product、jd_get_specs、jd_get_price；文档称有搜索引擎降级，非官方排序。许可及稳定性待核。

候选不是背书，安装前审核源码、版本和凭据处理。不安装未审查的批量抓取/会话提取工具，不绕过登录或验证码。平台阻止访问时改为用户链接/截图。

步骤：
1. 明确缺口、平台、单件预算、颜色/版型/面料/尺码条件。
2. 关键词由需求构造，过滤不符合硬约束的结果。
3. 打开少量候选详情，核对同一商品与所选 SKU，避免串价格。
4. 保存核验级别：search_result（仅搜索）；detail_verified（详情已读）；sku_verified（指定 SKU 的颜色/尺码/库存状态证据齐备）。这是记录完整度，不是质量认证。
5. 标价、价格币种、优惠条件、店铺、URL、抓取时间分别保存。会员/券后价不可默认可享；库存以查询时点为准。未知库存不能写 available。
6. 尺码依赖对应尺码表、衣服实测和用户习惯；只见 S/M/L 不承诺合身。生成图不作尺码证据。
7. 每个候选说明能搭哪些已有衣物，并提供不购买选项。

### 受控加购（可选）

- 默认只读。只有用户要求具体商品的加购，且宿主实际提供 `prepare_add_to_cart`、`confirm_add_to_cart` 与 `get_add_to_cart_status`，才使用该独立流程；总写操作开关仍保持关闭。
- 准备请求必须指定商品链接、颜色、尺码、数量。用户在已授权淘宝／天猫商品页手动选择规格与数量，工具核对页面实际选中状态；缺字段、多个选中项或不一致时停止，不猜默认 SKU。
- 准备成功只是待确认。优先调用实际提供的 `confirm_add_to_cart(request_id)`，由宿主在 Agent 内显示页面实测商品／规格／数量及已知价格条件，用户原生确认后直接操作网页，无需插件二次点击。模型不能自填 confirmed 或批准表单；宿主不支持原生确认时必须如实告知，可选择扩展弹窗替代，不冒称已自动完成。
- 请求短时有效，导航、授权变更或规格改变会失效。每个请求最多尝试一次；点击已发生不等于平台确认入车，未知结果先由用户检查，不自动重新提交或重试。
- 不进入购物车、订单、结算或支付页；不下单、不支付、不删除或修改其他购物车条目。加入购物车不代表已购买，不录入 wardrobe。京东与非扩展模式不使用本可选流程。

工具不可用：给搜索词/筛选条件而非伪造商品 URL；提供的平台搜索入口标记未核验。用户截图为用户提供证据，不能声称实时价格/库存。推荐里保留来源和时间；公开报告不包含账户、令牌、订单或收货地址。
